## 问题背景

### 1.1 核心问题

在使用配音平台进行有声作品配音时，存在两个主要问题：

#### 问题一：分段间音频的拼凑感

当文本被拆分成多个短句分别合成后，相邻分段的音频在拼接时存在明显的"拼凑感"，表现为：
- 语气不连贯
- 情感过渡生硬
- 节奏不自然

#### 问题二：情感控制需要反复"抽卡"

对于短句配音，即使提供了情感描述，合成的语音也经常不符合预期，需要：
- 反复调整情感描述文本
- 多次重新合成直到满意
- 耗费大量时间和精力

### 1.2 问题发现

用户在配音实践中发现了一个重要技巧：

**低质量情感描述**（LLM 默认生成）：
> 语气中的困惑加深，语速稍快，试图确认自己是否听错。

**高质量情感描述**（用户优化后）：
> 像刚被吵醒的熟睡者，语速较慢，非常困惑。

后者的效果显著更好，TTS 甚至在说话前加了一段打哈欠的声音。

## 技术分析

### 2.1 IndexTTS2 情感控制架构

经过对 IndexTTS2 源代码的深入分析，其情感控制架构如下：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        IndexTTS2 情感控制方式                            │
├─────────────────────┬───────────────────────────────────────────────────┤
│  情感参考音频        │  emo_audio → get_emb() → emo_cond_emb            │
│  (emotion_mode=1)   │  高维嵌入向量，包含韵律、语调、节奏等丰富信息        │
├─────────────────────┼───────────────────────────────────────────────────┤
│  8维情感向量         │  emo_vector → emo_matrix → emovec_mat            │
│  (emotion_mode=2)   │  [快乐,愤怒,悲伤,恐惧,厌恶,忧郁,惊讶,平静]          │
├─────────────────────┼───────────────────────────────────────────────────┤
│  情感描述文本        │  emo_text → Qwen3 → 8维向量 → 同上流程            │
│  (emotion_mode=3)   │  通过微调的 Qwen3 大模型理解文本并转换              │
└─────────────────────┴───────────────────────────────────────────────────┘
                              ↓
                    merge_emovec() 融合
                              ↓
                         最终 emovec
                              ↓
                    gpt.inference_speech()
```

### 2.2 关键发现

#### 发现一：emo_text 是大模型语义理解，不是简单标签匹配

```python
# indextts/infer_v2.py 第 783-789 行
def inference(self, text_input):
    messages = [
        {"role": "system", "content": "文本情感分类"},
        {"role": "user", "content": f"{text_input}"}  # emo_text 在这里
    ]
    # ... 调用 Qwen3 生成情感向量
```

这意味着：
- 可以使用任意自然语言描述
- 描述越具体，Qwen3 理解越准确
- 可以描述角色状态、场景、语速等

#### 发现二：情感参考音频提供最丰富的控制

情感参考音频被转换为高维嵌入向量（`emo_cond_emb`），包含：
- 韵律特征
- 语调变化
- 节奏模式
- 情感色彩

相比之下，8维情感向量是"标准化"的粗粒度控制。

#### 发现三：时长控制功能尚未启用

README 明确说明：
> "The first autoregressive TTS model with precise synthesis duration control... **This functionality is not yet enabled in this release.**"

这意味着目前无法实现"输入完整上下文，只生成指定句子"的理想方案。

### 2.3 当前参数配置

配音平台当前的 TTS 调用参数：

| 参数 | 当前值 | 说明 |
|------|--------|------|
| `use_random` | `False` | 不使用随机采样，保证音色克隆保真度 |
| `emotion_mode` | `3` (TEXT) | 使用文本情感描述模式 |
| `emotion_alpha` | `0.65` | 情感强度（README 建议文本模式用 0.6 或更低） |

## 解决方案

### 方案 A：优化 LLM 情感描述提示词

#### 原理

修改 LLM 分段提示词，让 LLM 生成更高质量的情感描述，遵循用户发现的技巧。

#### 描述结构

```
1. 角色状态（最重要）：像刚被吵醒的熟睡者、像在战场上的士兵
2. 语速节奏：语速较慢、语速急促、停顿较多
3. 情绪/情感：非常困惑、愤怒、悲伤
4. 声音质感（可选）：声音沙哑、轻声细语、嘶吼
```

#### 示例对比

| 场景 | 原始描述 | 优化后描述 |
|------|---------|-----------|
| 被吵醒 | 语气困惑，试图确认 | 像刚被吵醒的熟睡者，语速较慢，非常困惑 |
| 战斗中 | 愤怒地喊叫 | 像战场上的士兵，语速急促，充满愤怒和紧迫感 |
| 悲伤 | 声音低沉，悲伤 | 像刚失去亲人的人，语速缓慢，声音颤抖，极度悲伤 |

#### 实现方式

修改 `dubbing_service/app/routers/segments.py` 中的分段提示词模板。

#### 优点

- ✅ 实现成本极低（仅修改提示词）
- ✅ 立即生效
- ✅ 不需要用户额外操作

#### 缺点

- ❌ 不解决分段拼凑感问题
- ❌ 依赖 LLM 生成质量
- ❌ 短句上下文仍然不足

#### 实现成本

⭐ 极低（约 30 分钟）

---

### 方案 B：情感参考音频库 + 自动匹配

#### 原理

为每个角色预先配置多个情感参考音频，合成时根据情感描述自动匹配最接近的情感音频，使用 `emotion_mode=1`（情感参考音频模式）。

#### 架构设计

```
角色 (Role)
├── speaker_audio: 音色参考音频（决定声音）
└── emotion_audios: 情感音频库
    ├── happy.wav (标签: 快乐、开心、高兴)
    ├── sad.wav (标签: 悲伤、难过、伤心)
    ├── angry.wav (标签: 愤怒、生气、暴怒)
    ├── fear.wav (标签: 恐惧、害怕、惊恐)
    ├── surprised.wav (标签: 惊讶、意外、震惊)
    └── calm.wav (标签: 平静、自然、平和)
```

#### 匹配流程

```
1. 解析情感描述文本
2. 提取关键词或使用 LLM 分类
3. 匹配最接近的情感音频
4. 使用 emotion_mode=1 + emotion_audio 合成
```

#### 实现内容

1. **数据模型扩展**：角色增加 `emotion_audios` 字段
2. **UI 扩展**：角色编辑支持上传多个情感音频
3. **匹配逻辑**：根据情感描述匹配音频
4. **TTS 调用**：使用情感参考音频模式

#### 优点

- ✅ 情感控制最稳定（高维嵌入）
- ✅ 减少抽卡次数
- ✅ 情感表现更丰富

#### 缺点

- ❌ 不解决分段拼凑感问题
- ❌ 需要用户收集/录制情感音频
- ❌ 每个角色都需要配置
- ❌ 实现成本较高

#### 实现成本

⭐⭐⭐ 中等（约 2-3 天）

### 方案 C：智能合并短句 + 音频拆分

#### 原理

将相邻短句合并成长段落进行合成，然后根据静音检测或标记拆分音频，每个分段保留对应的音频片段。

#### 合成流程

```
原始分段：
  [1] "外面那个奇怪的声音是什么？"
  [2] "你刚才说什么？"
  [3] "我好像听到有人在敲门..."

合并合成：
  "外面那个奇怪的声音是什么？[PAUSE]你刚才说什么？[PAUSE]我好像听到有人在敲门..."

生成音频后拆分：
  audio_1.wav ← 第一句
  audio_2.wav ← 第二句
  audio_3.wav ← 第三句
```

#### 拆分方法

1. **静音检测**：使用 VAD 检测句子间的静音点
2. **时间对齐**：根据文本长度估算时间点
3. **标记法**：在文本中插入特殊标记，通过模型行为识别

#### 实现内容

1. **合并逻辑**：相邻 N 个分段合并
2. **音频拆分**：静音检测 + 切割
3. **映射存储**：合成结果映射回各分段

#### 优点

- ✅ 彻底解决拼凑感（同一次合成）
- ✅ 上下文充足，情感连贯
- ✅ 减少抽卡次数

#### 缺点

- ❌ 拆分精度可能有误差
- ❌ 实现复杂度高
- ❌ 调试困难

#### 实现成本

⭐⭐⭐⭐ 较高（约 4-5 天）

---

### 方案 D：上下文注入（推荐）

#### 原理

合成每个分段时，将前后文作为情感描述的一部分注入，让 Qwen3 理解完整上下文后生成更准确的情感向量。

#### 注入格式

```
【前文】"外面那个奇怪的声音是什么？"
【当前】"你刚才说什么？"
【后文】"我好像听到有人在敲门..."
【角色】小明（刚被吵醒的年轻人）
【场景】深夜，安静的卧室
【情感】像刚被吵醒的熟睡者，语速较慢，非常困惑
```

将整个增强描述传给 `emo_text`，Qwen3 会综合理解并生成情感向量。

#### 可配置参数

| 参数 | 说明 | 建议值 |
|------|------|--------|
| `context_before` | 注入前文数量 | 1-2 句 |
| `context_after` | 注入后文数量 | 1 句 |
| `include_role` | 是否包含角色信息 | 是 |
| `include_scene` | 是否包含场景信息 | 可选 |

#### 实现内容

1. **TTS Provider 修改**：构建增强情感描述
2. **上下文获取**：获取相邻分段文本
3. **可配置**：上下文窗口大小可调

#### 优点

- ✅ 部分解决拼凑感（Qwen3 理解上下文）
- ✅ 减少抽卡次数
- ✅ 实现成本低
- ✅ 不需要用户额外操作

#### 缺点

- ❌ 效果依赖 Qwen3 的理解能力
- ❌ 增加 emo_text 长度

#### 实现成本

⭐⭐ 低（约 1 天）

---

### 方案 E：多版本生成 + 快速选择

#### 原理

为每个分段生成多个版本，用户快速试听后选择最佳版本。

#### 生成方式

1. **随机采样**：使用 `use_random=True` 引入变化
2. **参数微调**：轻微调整 temperature、emotion_alpha
3. **情感变体**：自动生成情感描述的变体

#### UI 设计

```
分段 "你刚才说什么？"
├── [版本 1] ▶ 播放  ⭐ 选择
├── [版本 2] ▶ 播放  ☆ 选择
└── [版本 3] ▶ 播放  ☆ 选择
    [+ 生成更多版本]
```

#### 实现内容

1. **多版本生成**：调用 TTS 多次
2. **版本存储**：每个分段存储多个音频
3. **UI 扩展**：版本切换和选择界面

#### 优点

- ✅ 优化抽卡体验
- ✅ 用户控制权强
- ✅ 适合需要精细调整的场景

#### 缺点

- ❌ 不解决拼凑感
- ❌ 增加合成时间（N 倍）
- ❌ 增加存储空间
- ❌ 用户仍需手动选择

#### 实现成本

⭐⭐ 低（约 1-2 天）

## 实施建议

### 推荐路径

```
第一阶段（立即实施，1-2 天）
├── 方案 A：优化 LLM 情感描述提示词
└── 方案 D：上下文注入

第二阶段（短期，1-2 天）
└── 方案 E：多版本生成 + 快速选择

第三阶段（中期，根据效果决定）
├── 若情感仍不稳定 → 方案 B：情感音频库
└── 若拼凑感严重 → 方案 C：合并拆分
```

### 第一阶段详细计划

#### 任务 1：优化 LLM 分段提示词（方案 A）

**修改文件**：`dubbing_service/app/routers/segments.py`

**修改内容**：更新提示词模板，要求 LLM 按以下结构生成情感描述：
```
1. 角色当前状态（如：像刚被吵醒的熟睡者）
2. 语速节奏（如：语速较慢）
3. 核心情绪（如：非常困惑）
4. 声音特征（可选，如：声音沙哑）
```

**预计耗时**：30 分钟

#### 任务 2：实现上下文注入（方案 D）

**修改文件**：`dubbing_service/app/providers/tts.py`

**修改内容**：
1. `_build_payload` 方法接收上下文参数
2. 构建增强的情感描述文本
3. 传递给 `emotion_text` 字段

**修改文件**：`dubbing_service/app/routers/synthesis.py`

**修改内容**：
1. 合成时获取当前分段的前后文
2. 传递给 TTS Provider

**预计耗时**：1 天
