# AI 有声导演工作室：生产化重构与功能升级方案

## 1. 文档定位

本文是配音平台的产品边界、实施路线与验收基线。下方“实施状态”记录当前完成度；具体运行架构与恢复环境仍以 [architecture.md](architecture.md) 和 [recovery_report.md](recovery_report.md) 为准。

### 1.1 实施状态（2026-07-11）

本文所定义的三个里程碑现已完成第一轮可用实现，后续迭代以实际制作反馈、音质对比和缺陷修复为主，不再扩张到视频或平台运营功能。

| 里程碑 | 已实现基线 |
| --- | --- |
| 一：可靠配音与编辑 | 独立 A/B 槽位、不可变 Take、最终 Take 选择、历史恢复与固定、完全非破坏 EditRecipe、渲染为新 Take、有限编辑修订、后端持久合成任务及重启恢复 |
| 二：专业人声与质检 | 原文与播音分段分离、章节/场景、Voice Bible 与声音授权、项目发音词典、审听状态与问题分类、连续试听和批量通过、人声预设/淡化/首尾静音、自动完整性与音频质检 |
| 三：声音设计与发布 | Dialogue/BGM/Ambience/SFX 四轨、本地素材授权与哈希、时间定位/裁剪/循环/淡化/增益、BGM 自动闪避、对白交叉淡化、响度与 True Peak 母带、不可变 Master、WAV/MP3/SRT/VTT/封面/元数据/授权/校验和发布包 |

当前声音设计界面刻意采用表格式时间线和少量可理解参数，而不是完整 DAW；音乐和音效生成模型仍仅保留接口方向，没有部署。这两点属于本文确定的产品边界，不是缺失功能。

项目只有一个核心目标：

> 将故事、资讯、知识内容、播客文稿等文本，稳定地制作成高质量、可审听、可修改、可发布并可用于收益的有声作品。

所有后续建设都用四个问题判断优先级：

1. 是否能让成品更好听？
2. 是否能降低音频、编辑或项目数据丢失的风险？
3. 是否能明显提高制作和审听效率？
4. 是否能让最终发布文件更完整、可信和可复现？

不能满足其中任何一项的功能，本轮不做。

## 2. 产品边界与核心流程

本项目定位为本地优先、单人使用、桌面 Web UI 的 AI 有声工作室，不建设通用音视频创作平台或企业内容管理系统。

核心制作流程为：

```text
文本导入
  → 智能或手动分段
  → 角色与音色配置
  → TTS Take 生成
  → A/B 审听与最终选择
  → 非破坏性编辑
  → BGM、环境声与 SFX
  → 混音与母带
  → 质量检查
  → 音频、字幕、封面与发布信息
```

第一阶段明确不建设：

- 视频生成、视频编辑和视频轨道。
- 喜马拉雅、今日头条、番茄畅听、抖音等平台的直接发布 API。
- 播放量、收益和运营分析。
- 多用户、权限、团队协作、云同步和远程项目管理。
- 企业级数据分类和内容治理。
- 自动网络采集和复杂事实核查系统。
- 完整专业 DAW 所具备的无限轨道、插件宿主和复杂自动化能力。
- IndexTTS2、Qwen3-TTS、CosyVoice3 之外的更多 TTS 模型。
- 在核心声音设计流程稳定前部署新的 BGM/SFX 生成模型。

保留最基本的声音授权、音乐和音效来源及许可证记录，因为这些信息直接关系到作品能否用于商业发布。

## 3. 目标架构

### 3.1 内容与音频对象

采用足够表达制作流程、但不过度复杂的结构：

```text
Project 作品
├── Chapter / Scene 章节或场景
│   └── Segment 分段
│       ├── A Take
│       ├── B Take
│       └── Archived Takes 历史版本
└── Master 成品版本
```

核心对象职责如下：

| 对象 | 职责 |
| --- | --- |
| `Segment` | 保存播音文本、角色、顺序、审听状态和最终采用的 Take |
| `Take` | 保存一次不可变的 TTS 结果及其模型、音色、提示、参数、原始音频和文件哈希 |
| `EditRecipe` | 保存作用于某个 Take 的非破坏编辑参数，不直接修改原始音频 |
| `Job` | 保存合成、预览、渲染、导出等后台任务的状态、进度和错误 |
| `Master` | 冻结最终 Take、编辑方案、声音素材、混音参数和输出文件 |
| `Timeline` | 保存 Dialogue、BGM、Ambience、SFX 四轨的片段和时间位置 |

### 3.2 TTS 与文本模型

保留三个 TTS 系列，并继续使用独立 uv 虚拟环境和独立 Worker：

- IndexTTS2：主要用于故事和情绪化表达。
- Qwen3-TTS CustomVoice / VoiceDesign：主要用于角色音色设计和自定义音色。
- CosyVoice3：作为补充音色和生成能力。

平台统一提供启动、停止、健康检查、超时、日志、失败恢复和显存互斥。任一时刻最多只让一个大型本地模型占用 GPU。模型文件统一保存在项目 `models/` 目录规定的位置。

DeepSeek 只承担文本分段、角色识别、播音稿整理、口语化改写和演绎建议。手动分段和编辑必须始终可用，云端服务故障不能阻塞制作。首次启用云端文本处理时明确提示正文会发送到所配置的服务，不建设企业级数据治理界面。

## 4. 里程碑一：配音、A/B、编辑与任务可靠性

### 4.1 A/B 与不可变 Take

历史版本的 A/B 曾通过交换主音频和备用音频字段工作，版本参数和编辑状态也没有完全隔离。当前第一轮实现已改为以下基线，后续回归必须继续满足：

- A、B 改为两个独立槽位，分别引用独立 Take。
- 切换 A/B 只改变当前查看版本，不交换、不覆盖任何字段或文件。
- 每个 Take 独立保存模型、音色、语言、情绪、提示词、随机种子、生成参数、耗时、日志和原始文件哈希。
- 每个 Segment 明确保存最终采用的 Take，整书合成不依赖当前界面停留在哪个标签。
- 重新生成成功后才替换对应槽位；生成失败、Worker 中断或文件校验失败时，原 Take 保持不变。
- 被替换的 Take 进入隐藏历史，可试听、恢复到 A/B、固定或手动删除。
- 默认保留最近 90 天且每段最多 20 个未固定历史 Take；被固定或被 Master 引用的 Take 永不自动清理。

旧项目迁移必须先备份并生成迁移报告：根据旧 `active_version` 和交换规则恢复 A/B 身份；无法可靠还原的共享参数保留到当前活动版本并标记为需要人工复核，不静默猜测。

### 4.2 完全非破坏编辑

历史版本只有预览和按编辑草稿导出是非破坏性的，“应用处理”和“删除选区”仍会覆盖分段原始音频。当前第一轮实现已统一为以下规则，后续不得恢复覆盖式编辑：

- TTS 生成的原始 Take 永远只读，所有编辑不得改变其文件哈希。
- 裁剪、删除区间、插入静音、语速、增益、淡入、淡出和片段间距都保存为 `EditRecipe`。
- 波形预览只生成可清理的派生缓存。
- “保存编辑”只保存 EditRecipe，不生成或覆盖原始音频。
- 用户主动执行“渲染为新 Take”时才固化编辑结果，并创建有来源关系的新 Take；原 Take 继续保留。
- A、B 和历史 Take 分别拥有独立 EditRecipe。
- 编辑方案保留有限修订历史，支持撤销、重做和恢复原始状态。
- Master 和发布导出统一通过相同渲染管线应用 EditRecipe，避免预览与成品结果不一致。

### 4.3 持久任务队列与 Worker

- 将浏览器内存中的合成队列迁移到后端持久化任务存储。
- 任务状态统一为 `queued`、`running`、`succeeded`、`failed`、`cancelled`、`interrupted`。
- 平台重启后继续未开始的 queued 任务；异常退出时将 running 标记为 interrupted，由用户安全重试。
- 每次任务拥有幂等标识，重试不覆盖旧 Take，也不产生无法归属的重复文件。
- 支持单段、选中段落、失败段落和全部段落的批量生成与重试。
- 抽离统一 WorkerManager，管理四个 TTS 后端工作进程的身份、健康检查、启动超时、错误日志、显存互斥和优雅退出。

### 4.4 核心 UI 重构

桌面端主流程固定为：

```text
脚本 → 音色 → 配音审听 → 声音设计 → 导出
```

UI 保持简约、明确、优雅和符合直觉：

- 左侧为作品、章节和场景导航，中间为当前工作区，右侧为当前对象属性，底部为可收起的任务与 Worker 状态。
- 每个分段默认突出正文、角色、生成状态、播放、A/B 和最终选择。
- A/B 使用两个清晰的独立标签或卡片；历史 Take 放在按需展开的版本抽屉中。
- 常用参数直接显示，高级模型参数渐进展开。
- 生成中、生成失败、待审听、需修改、已通过和已采用使用一致且克制的状态视觉。
- 永久删除等危险操作与生成、播放、保存等常用操作分离。
- 保留批量选择、连续播放、键盘快捷键和快速跳到下一条待处理分段。
- 前端按功能渐进拆分，先保证行为正确，再调整布局和视觉，不进行一次性推翻式重写。

### 4.5 里程碑一验收

- A/B 按任意顺序生成、切换、编辑、清除和恢复，双方音频及参数均不互相覆盖。
- 所有普通编辑操作前后，原始 Take 文件哈希保持一致。
- 生成、文件写入或元数据保存失败不会破坏原 Take 和槽位引用。
- 平台、浏览器或 Worker 重启后，任务、A/B、编辑草稿和最终选择完整恢复。
- IndexTTS2、Qwen3 CustomVoice/VoiceDesign 和 CosyVoice3 均通过真实中文短句合成测试。
- 旧项目完成备份、迁移、试听对比和回滚演练。

## 5. 里程碑二：专业人声制作与质量控制

### 5.1 脚本、角色与发音

- 原始文本和可编辑播音稿分开保存，任何口语化处理不得覆盖原文。
- 支持章节、场景和分段组织；故事模式默认忠实原文，资讯、知识和播客模式允许生成可审阅的口语化版本。
- 建立轻量 Voice Bible，保存角色默认模型、音色、语言、参考音频、语速范围和演绎倾向。
- 建立项目级发音词典，处理人名、地名、数字、英文缩写、多音字和专业名词。
- 修改角色音色或发音规则时显示影响范围，不自动覆盖或重新生成现有 Take。

### 5.2 审听工作流

Segment 状态简化为：

```text
待生成 → 待审听 → 需修改 → 已通过
```

提供连续播放、A/B 快速切换、批量通过、跳到下一条待审听分段，以及发音、情绪、节奏、停顿、文本和音质问题标记。根据问题重新生成时始终创建新 Take。

### 5.3 人声编辑与处理

在里程碑一的非破坏编辑基础上补充：

- 多段裁剪、停顿调整、淡入淡出和相邻片段交叉淡化。
- 分段增益、语速和段落间距调整。
- 开头、结尾静音设置。
- 可选的人声 EQ、压缩和限制器预设。

默认只暴露“自然对白”“有声故事”“清晰播客”等可理解的预设；专业参数放在高级面板，避免把平台变成复杂 DAW。

### 5.4 自动质量检查

- 检查缺失或损坏音频、异常静音、削波、音量突变和明显异常时长。
- 检查漏段、重复段、顺序异常和未审听内容。
- 检查字幕来源与最终音频哈希是否匹配。
- 检查 Master 是否引用缺失或已失效的文件。
- 自动检查只提供问题定位和修复入口，不擅自修改已通过内容。

### 5.5 里程碑二验收

- 能从长篇故事或播客文稿完成一条连续、自然、响度稳定的纯人声作品。
- 同一角色跨章节使用一致的音色和发音规则。
- 发音、情绪、停顿和文本问题能够快速标记、重生成和复核。
- 正式 Master 默认拒绝包含缺失音频或未通过审听的分段；预览导出必须明确标记。
- 已生成 Master 不会被后续编辑或重新生成改变。

## 6. 里程碑三：声音设计、混音母带与发布包

### 6.1 四轨时间线

声音设计只提供有声作品需要的四类轨道：

- `Dialogue`：对白和旁白。
- `BGM`：背景音乐。
- `Ambience`：持续环境氛围。
- `SFX`：事件型音效。

支持本地素材导入、试听、时间点放置、移动、裁剪、循环、淡入淡出、基础音量包络、场景级复用，以及 BGM 对 Dialogue 的自动闪避。不建设无限轨道、第三方音频插件宿主或复杂自动化曲线。

### 6.2 本地素材库

- BGM、Ambience 和 SFX 支持分类、标签、搜索、收藏和项目引用查询。
- 每项素材记录来源、作者、许可证、商业使用说明和文件哈希。
- 删除素材前检查项目和 Master 引用；被引用素材不得静默删除。
- 预留统一 `AudioGenerationProvider` 接口，但本里程碑不要求部署音乐或音效生成模型。
- 后续模型必须满足本机可运行、可以从魔塔保存到项目目录、商业授权清晰和结果可复现后，才能进入候选实施计划。

### 6.3 混音与母带

- Dialogue、BGM、Ambience 和 SFX 分别控制电平、静音和独听。
- 提供有声故事、自然对白和清晰播客等母带预设。
- 支持响度标准化、True Peak 限制、防削波、整体淡入淡出以及单声道或立体声衍生输出。
- 生成 Master 前执行完整性和音频质量检查。
- Master 冻结所用 Take、EditRecipe、时间线、素材、混音参数、输出参数和输入文件哈希。

### 6.4 发布包

一次发布导出至少生成：

- 高质量 WAV Master。
- MP3 或 M4A 发布版本。
- SRT、VTT 字幕。
- 章节信息。
- 封面文件。
- 标题、简介和节目说明。
- 所用模型、声音、音乐和音效记录。
- 输出文件校验和。

平台只提供通用发布包和可配置导出预设，不直接登录或上传第三方平台。

### 6.5 里程碑三验收

- 能完整制作包含人声、BGM、环境声和 SFX 的有声作品。
- BGM 自动闪避能够保证对白清晰，场景切换和音效衔接自然。
- 同一 Master 可以稳定生成所需格式，重复导出的输入和参数可追溯。
- 字幕、章节、说明和校验和均与最终 Master 对应。
- 发布包可用于人工上传目标平台，不依赖平台专属 API。

## 7. 贯穿实施的工程整理

工程整理只服务于核心制作能力，不单独开展无目标重写：

- 将超大前端页面渐进拆分为脚本、音色、配音审听、声音设计和导出模块。
- 将路由中的数据库、文件、FFmpeg 和 Worker 业务迁入可测试的服务层。
- 统一媒体目录、文件命名、配置、日志、错误提示和任务关联 ID。
- 为数据结构建立版本迁移、自动备份、恢复和完整性检查。
- 清理文件前验证 Segment、Take、Master 和素材引用；无法确定用途的文件先进入隔离区。
- 为 A/B、非破坏编辑、任务恢复、三模型合成、质量检查、混音和发布导出建立自动化测试。

实施始终按“先保护数据，再修正核心流程，然后提升音质，最后增加声音设计”的顺序推进。任何新功能不得以破坏现有作品、旧项目兼容性或本机稳定运行为代价。
