## Guarded inference

One serial GPU worker; baseline and candidate models never reside together. No supported batching or streaming is advertised. TTFA is unmeasured because this is nonstreaming synthesis. Missing CUDA, invalid checkpoint, incompatible versions, malformed input, concurrent adapter use, empty/nonfinite output, token cap, exhausted token budget, cancellation and OOM fail clearly. There is no automatic or spliced fallback. Successful output records the profile, package, seed/settings, EOS reason and token counts.

Saved conditioning is content-hash verified and cached by existing Studio logic. Faster receives the precomputed prompt, avoiding its path-only reference cache. `append_silence=False` preserves the existing reference treatment. Predictor controls are set before graph capture; public talker and predictor sampling settings must match current production settings. Graph warmup precedes per-request seed reset. Each request uses the existing stable identity+text seed rule. Identical weights do not establish audio parity.

Executable tests confirm a Faster 0.3.2 top-p boundary difference from Transformers 4.57.3: probabilities .6/.3/.1 with p=.8 retain only the first token in Faster versus two in HF. Current production p=1 passes the mask comparison. Altered sampling controls are rejected rather than silently reinterpreted.

The static sequence cap is 2048 including prefill. The adapter checks prefill plus the existing production token budget before generation and rejects a request that cannot fit. It also distinguishes EOS from cap or exhausted budget using the verified pinned implementation. A five-minute single call is unsupported. Production must retain segmentation, and complete tails still require transcript/listening review: EOS and finite waveforms do not prove every word was spoken.

The experimental cancellation endpoint is `/api/v1/tts/character/cancel`. It targets the active request on this serial worker and is not a per-job cancellation API. It remains local; the private comparison UI has no generation or cancellation actions. Existing production job cancellation between segments remains authoritative. Cancellation during conditioning/loading is remembered, and interrupted output is not published as a successful Take. The next request gets a new cancellation event.


## Runtime-bound jobs and cached takes

The worker exposes `/api/v1/tts/runtime-identity` without loading weights. Its process-frozen digest covers the approved absolute Base checkpoint/manifest, package versions, implementation sources, dtype/attention, sampling and seed policy, token budget and disabled fallback. Changes to those inputs on disk require restart. Requests send the expected worker digest; a mismatch returns 409 under the inference lease before loading or synthesis. Success metadata must return that same digest and no fallback.

The renderer adds its implementation/chunk policy to that contract. Jobs persist per-backend runtime bindings before dispatch across their complete planned scope; each chunk checks the worker again. Take fingerprints include actual runtime provenance. Resume checks references, role aliases, selected takes and settings before using cached output. Missing worker endpoints, mismatched provenance, and legacy completed Qwen audio without a binding fail clearly. An operator must explicitly start a new whole rendition to change runtime; completed historical audio is preserved. Cancellation, OOM or an uncertain bound-worker failure does not trigger automatic reassembly/retry or runtime switching. CustomVoice remains separate; its checkpoint is present and CPU contracts were checked, but no new CustomVoice GPU sample was generated.

This closes the recoverable resume gap: a job cannot silently append Faster chunks to a native rendition or the reverse. Actual wrong-digest HTTP returned 409 without model load/audio. Existing completed jobs keep their recorded status without requiring a live worker lookup. Legacy audio is retained but cannot be silently reused as runtime-bound output.
