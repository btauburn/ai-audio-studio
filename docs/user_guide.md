# 有声作品制作使用指南

本指南描述当前 WebUI 的实际生产流程：脚本与音色 → 配音审听 → 声音设计 → 导出发布。界面中的编辑和选择围绕“保留原始素材、明确人工决策、可追溯交付”设计。

## 1. 启动与后端选择

打开 `http://127.0.0.1:9000/web/`，进入“平台配置”选择并启动一个后端：

| 后端 | 适合场景 | 是否需要参考声音 |
| --- | --- | --- |
| IndexTTS2 | 主力旁白、角色克隆、8 维情绪或情感参考 | 需要 |
| Qwen CustomVoice | 快速使用稳定内置音色，并用文字控制风格 | 不需要 |
| Qwen VoiceDesign | 根据文字描述设计新音色 | 不需要 |
| CosyVoice3 | 参考声音 + 自然语言风格指令 | 需要 |

平台同一时间只运行一个 GPU TTS 工作进程。保存新的默认后端不会自动替换已经运行的模型；请先停止旧后端，再启动目标后端。

## 2. 创建项目与角色

在“项目工作区”点击“新建项目”，填写名称、描述和内容类型。建议一个作品或一期播客使用一个项目。

随后在“脚本 & 音色”中创建角色：

- 旁白、主持人、嘉宾和故事角色分别建角色；
- IndexTTS2/CosyVoice3 角色绑定 3～10 秒干净参考声音；
- Qwen CustomVoice 角色选择内置 speaker 与语言；
- Qwen VoiceDesign 角色填写稳定、具体的音色描述；
- 角色级后端优先于全局后端，分段级后端优先于角色级后端。

参考声音应只有一个说话人、无背景音乐、无明显混响或削波，并且已经取得合法使用授权。

## 3. 导入与分段脚本

有三种方式：

1. 粘贴原文，调用 DeepSeek 自动分段；
2. 导入外部 LLM 生成的 JSON 数组；
3. 手工创建和调整分段。

自动分段默认优先 `deepseek-v4-flash`，在允许回退的可重试失败或输出校验失败时最多尝试一次 `deepseek-v4-pro`。认证失败、权限错误和参数错误不会通过换模型掩盖。

分段后必须人工检查：

- 原文是否完整覆盖、有没有漏句或重句；
- 说话人是否正确；
- 单段是否过长；
- 情绪、语速和停顿描述是否符合上下文；
- 专有名词、数字、英文缩写和多音字是否需要发音词典。

“声音设计 → 项目发音词典”只会修改发送给 TTS 的文本副本，不会改写原始脚本，也不会覆盖已经生成的 Take。

## 4. 生成与比较 Take

每个分段有独立的 A/B 槽位，槽位中保存不可变 Take：

1. 在 A 槽生成第一版；
2. 点击“A/B”进入 B 槽；
3. 修改情绪、音色描述、随机种子或后端参数后生成第二版；
4. 在 A、B 间切换试听；
5. 对满意的一侧点击“采用 A”或“采用 B”。

在一侧重新生成不会删除另一侧。被新生成结果替换的旧 Take 会进入“历史”，可以试听、固定或恢复到 A/B。只有明确点击清除时才回收可清理版本；重要版本建议先固定。

最终整合使用“已采用”的 Take，而不是当前界面恰好显示的槽位。生成完每一段后都确认“✓ 已采用”状态。

## 5. 非破坏编辑

波形编辑默认保存为编辑配方，不改写原始 Take。可使用：

- 区间裁剪和静音；
- 音量、速度；
- 淡入、淡出；
- 头部和尾部留白；
- 预览编辑结果。

保存配方后，原始音频仍然存在。只有点击“渲染为新 Take”时才会生成一个新的派生音频；新 Take 也不会覆盖来源 Take，来源仍在历史中可追溯。

推荐做法：先保留未经处理的最佳 TTS Take，再用配方完成轻量修整；需要反复加工或跨项目复用时，才渲染为新 Take。

## 6. 审听

每段都有人工审听状态：待审听、需修改、已通过。建议按以下顺序听：

1. 单段音质：错字、吞字、爆音、削波、底噪；
2. 角色一致性：音色、口音、年龄感；
3. 表演：情绪、重音、停顿、语速；
4. 上下文衔接：相邻两段的能量与节奏；
5. 连续审听：整章或整期是否自然。

发现问题时点击“标记问题”，记录 pronunciation、emotion、pacing、text、audio 或 other。问题解决并重新试听后再标记“已通过”。

“批量通过可审分段”只适合已经实际听完且没有未解决问题的内容。正式 Master 要求所有分段都已通过。

## 7. 声音设计

“声音设计”提供四轨逻辑：

- Dialogue：由所有已采用 Take 自动生成；
- BGM：背景音乐；
- Ambience：环境底声；
- SFX：短促音效。

导入素材时记录名称、来源、作者、许可证、是否确认可商用和文件哈希。没有明确商业授权的素材不要进入商业发布 Master。

时间线片段可以设置位置、裁剪范围、循环、增益和淡入淡出。混音区还可设置各轨总增益、对白交叉淡化和 BGM 自动闪避。

实用原则：

- 先保证对白清楚，再加音乐和音效；
- BGM 不要持续与人声争夺中频；
- SFX 应服务叙事，不要为了“热闹”频繁堆叠；
- 环境声宜稳定、低存在感，循环点不能明显；
- 使用自动闪避后仍需完整试听，避免音乐忽大忽小。

当前版本使用本地已有音乐和音效，不会自动部署或调用音乐生成模型。

## 8. 预览、质检与 Master

在“导出发布”中先点击“导出预览音频”。预览用于检查，不冻结当前工程。

完成全片试听后运行质量检查。重点处理阻断项：

- 缺失或未采用 Take；
- 分段未通过审听；
- 音频文件或哈希异常；
- 素材授权记录缺失；
- 响度、真峰值或格式不符合要求。

全部通过后点击“生成正式 Master”。Master 会冻结当时使用的 Take、编辑配方和文件校验值，是不可变的发布候选；后续修改工程不会悄悄改变旧 Master。

建议按平台和节目类型保留不同 Master 名称，例如“播客标准版”“故事纯人声版”“短视频节选版”。

## 9. 字幕与发布包

字幕可选择：

- `large-v3-turbo`：中英文默认推荐；
- `large-v3`：质量优先、速度更慢；
- `distil-large-v3`：只建议纯英文。

自动字幕仍需人工校对人名、专有名词、数字、标点和断句。

对目标 Master 点击“生成发布包”。通用 ZIP 可包含：

- WAV 和 MP3；
- SRT 和 VTT；
- 章节信息；
- 封面；
- 标题、简介等元数据；
- 声音、音乐和音效的授权/署名清单；
- 文件校验和。

本项目不会自动上传喜马拉雅、今日头条、番茄畅听或抖音。发布前在各平台后台人工核对当期格式、响度、封面、AI 内容标识和授权要求。

## 10. 建议的日常生产节奏

一次稳定的节目制作可以按以下节奏执行：

1. 整理原稿和角色表；
2. 分段并校正文案；
3. 先用 3～5 段锁定音色和参数；
4. 批量生成，其间不要切换 TTS 后端；
5. 逐段 A/B、非破坏编辑并审听；
6. 连续听完整 Dialogue；
7. 加 BGM、Ambience、SFX；
8. 导出预览，在耳机和普通扬声器上复听；
9. 质检并生成 Master；
10. 校对字幕、补齐元数据和授权，生成发布包；
11. 将工程数据和最终发布包做冷备份。

## 11. 不要这样做

- 不要同时运行两个平台实例写同一个项目目录；
- 不要把三个 uv 环境合并；
- 不要在模型运行时切换或删除模型目录；
- 不要用“渲染为新 Take”替代正常的编辑配方保存；
- 不要在未完整试听时批量标记通过；
- 不要把 API Key、作品、声音、模型或输出强制加入 Git；
- 不要把无认证的 9000 端口暴露公网；
- 不要把技术可用误当作已经取得商业授权。
