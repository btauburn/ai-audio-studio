# 有声作品制作使用指南

本指南对应当前 WebUI 的实际生产流程：**脚本与音色 → 配音审听 → 声音设计 → 导出发布**。如果尚未完成环境、模型和首次样音，请先阅读 [新机安装与模型配置](installation.md)。

> [!WARNING]
> LLM 自动分段和“从 JSON 导入分段”都会重建当前项目的分段列表。已有 Take、编辑或审听结果的项目在重新分段前必须先备份；第一次尝试应使用独立测试项目。

## 术语

| 术语 | 含义 |
| --- | --- |
| Take | 一次 TTS 生成或派生渲染得到的不可变音频版本 |
| A/B 槽位 | 当前用于对比的两个 Take 位置；槽位不是音频文件本身 |
| 已采用 Take | 最终对白时间线实际使用的版本，与当前页面正在显示哪一侧无关 |
| 编辑配方 | 裁剪、静音、音量、速度、淡化等非破坏参数，不改写来源 Take |
| Preview | 当前工程状态的试听导出，不冻结工程 |
| Master | 通过审听和质检后冻结的不可变发布候选 |
| Release Package | 基于某个 Master 生成的音频、字幕、元数据、授权记录和校验和 ZIP |

## 1. 先看完整流程

一次作品制作通常按以下顺序进行：

1. 创建项目，选择作品类型并建立章节/场景；
2. 建立角色 Voice Bible，配置音色与声音授权；
3. 导入原文并生成或手工整理分段；
4. 生成 Take，在 A/B 间比较并采用最终版本；
5. 保存非破坏编辑，逐段和连续审听；
6. 加入 BGM、Ambience、SFX 并记录素材授权；
7. 导出 Preview，完成质量检查并冻结 Master；
8. 校对字幕和发布信息，生成 Release Package；
9. 完整复听并冷备份。

界面的四个主要工作区分别是“脚本 & 音色”“配音审听”“声音设计”“导出发布”。

## 2. 启动并选择 TTS 后端

打开 `http://127.0.0.1:9000/web/`，进入“平台配置”选择并启动一个已经安装的后端：

| 后端 | 适合场景 | 参考声音 | 授权注意 |
| --- | --- | --- | --- |
| IndexTTS2 | 旁白、角色克隆、8 维情绪或情感参考 | 需要 | 辅助模型集合含标记为 CC-BY-NC-4.0 的 MaskGCT；商业使用前必须单独解决 |
| Qwen CustomVoice | 快速使用内置音色，并用文字控制风格 | 不需要 | 以 manifest 固定版本及随附许可为准 |
| Qwen VoiceDesign | 根据文字描述设计新音色 | 不需要 | 以 manifest 固定版本及随附许可为准 |
| CosyVoice3 | 参考声音 + 自然语言风格指令 | 需要 | 以 manifest 固定版本及随附许可为准 |

平台同一时间只运行一个 GPU TTS 工作进程。保存新的默认后端不会替换已经运行的模型；切换时应先停止旧后端，再启动目标后端。

技术可运行不等于取得商业权利。除模型许可外，还要分别确认参考声音、原文、音乐、音效和发布平台规则，详见 [NOTICE](../NOTICE.md)。

## 3. 创建项目、章节与角色 Voice Bible

在“项目工作区”点击“新建项目”，填写名称、描述和内容类型。建议一部作品或一期播客使用一个项目。

在“脚本 & 音色”中先整理作品结构：

- 选择有声故事、资讯、知识内容或播客；
- 按需要新建章节/场景；
- 后续为分段指定章节归属；
- 不建章节也可以按全篇顺序制作。

随后为旁白、主持人、嘉宾和故事人物分别创建角色。角色资料相当于项目的 Voice Bible，建议至少记录：

- 角色类型、描述、年龄感、口音和表演方向；
- 角色默认 TTS 后端；
- 参考声音或内置音色；
- Qwen speaker、语言、VoiceDesign 描述或风格指令；
- 声音来源、许可证或授权名称、是否确认可商用。

后端配置优先级为：分段级 > 角色级 > 全局默认。

IndexTTS2/CosyVoice3 建议使用 3～10 秒干净参考声音。参考音频应只有一个说话人，无背景音乐、明显混响或削波，并且已经取得明确授权。Qwen CustomVoice 选择内置 speaker 与语言；Qwen VoiceDesign 使用稳定、具体的音色描述。

## 4. 导入原文与分段

可使用三种方式：

1. 粘贴原文，调用 DeepSeek 自动分段；
2. 导入外部 LLM 或其他工具生成的 JSON；
3. 手工创建、拆分、合并和调整分段。

> [!IMPORTANT]
> 自动分段和 JSON 导入不是“追加”，而是替换当前分段列表。已有正式工作的项目应先运行冷备份；试验新的分段规则时，应新建测试项目再操作。

DeepSeek 默认优先使用 `deepseek-v4-flash`；遇到允许回退的网络/服务错误或输出校验失败时，最多尝试一次 `deepseek-v4-pro`。认证、权限和参数错误不会通过换模型掩盖。发送给 DeepSeek 的原始文本会离开本机；敏感内容应手工处理或使用本地生成的 JSON。

推荐的 JSON 是对象数组：

```json
[
  {
    "speaker_name": "旁白",
    "text": "夜色慢慢降临，远处的灯火依次亮起。",
    "emotion_description": "平静、舒缓，略带期待"
  },
  {
    "speaker_name": "林舟",
    "text": "我们从这里出发。",
    "emotion_description": "坚定，语速稍慢"
  }
]
```

每项至少需要非空 `text`；`speaker_name` 和 `emotion_description` 可以按实际内容填写。导入后要检查新建角色和角色绑定是否正确。

分段完成后必须人工检查：

- 原文是否完整覆盖，有没有漏句、重句或改写；
- 说话人和章节归属是否正确；
- 单段是否过长；
- 情绪、语速和停顿是否符合上下文；
- 专有名词、数字、英文缩写和多音字是否需要发音词典。

“声音设计 → 项目发音词典”只修改发送给 TTS 的文本副本，不改写原始脚本，也不会覆盖已生成的 Take。

## 5. 批量合成与持久任务

先用 3～5 个代表性分段锁定音色、语言和参数，再点击“批量合成所有分段”。不要用整部长篇作品测试一个未经试听的新配置。

批量合成由持久任务记录进度：

- 可在“当前任务”查看项目、完成数、失败数和状态；
- 正常停止时使用“停止批量合成”，不要直接结束 Python 进程；
- 平台或系统中断后，重新打开项目会显示断点提示，可点击“继续合成”；
- 已完成分段会保留，待处理或失败分段可以继续；
- 批量期间不要启动、停止或切换 TTS 后端。

平台使用一把全局 TTS/GPU 租约，同一时间只允许一个受管合成批次。跨项目并行合成或批次期间切换模型被拒绝是保护行为，不是故障。

## 6. 生成和比较 Take

每个分段有独立的 A/B 槽位，槽位中引用不可变 Take：

1. 在 A 槽生成第一版；
2. 点击“A/B”进入 B 槽；
3. 修改情绪、音色描述、风格指令或分段后端；
4. 在 B 槽生成第二版；
5. 来回切换试听；
6. 对满意的一侧点击“采用A”或“采用B”。

在一侧重新生成不会删除另一侧。被新结果替换的旧 Take 会进入“历史”，可以试听、固定或恢复到 A/B。只有明确清理时才会回收可清理版本，重要版本应先固定。

最终 Dialogue 使用“已采用”的 Take，而不是界面当前显示的槽位。生成完每一段后都确认“✓ 已采用”。

## 7. 非破坏编辑

波形编辑默认保存为编辑配方，不改写原始 Take。当前支持：

- 区间裁剪和静音；
- 音量与速度；
- 淡入、淡出；
- 头部和尾部留白；
- 人声预设和编辑结果预览。

点击“保存编辑”后，配方会随项目持久化，来源音频仍然存在。只有点击“渲染为新 Take”时才会生成派生音频；新 Take 不会覆盖来源，来源仍可从历史追溯。

推荐先保留未经处理的最佳 TTS Take，再用配方做轻量修整。只有需要固化、跨步骤复用或比较渲染结果时，才生成新 Take。

## 8. 人工审听

每段都有待审听、需修改、已通过三种人工状态。建议按以下顺序检查：

1. 单段音质：错字、吞字、爆音、削波和底噪；
2. 角色一致性：音色、口音和年龄感；
3. 表演：情绪、重音、停顿和语速；
4. 上下文衔接：相邻两段的能量与节奏；
5. 连续审听：整章或整期是否自然。

发现问题时点击“标记问题”，选择 pronunciation、emotion、pacing、text、audio 或 other，并记录具体原因。修复并重新试听后再标记“已通过”。

“批量通过可审分段”只适合已经实际听完且没有未解决问题的内容。正式 Master 要求全部分段都已采用 Take 且审听通过。

## 9. 声音设计与素材授权

“声音设计”使用四轨逻辑：

- Dialogue：由所有已采用 Take 自动生成；
- BGM：背景音乐；
- Ambience：环境底声；
- SFX：短促音效。

导入本地素材时记录名称、来源、作者、许可证、是否确认可商用和文件哈希。没有明确商业授权的声音、音乐或音效不得进入商业发布 Master。

SFX 与 Ambience 也可由本地 Stable Audio 3 Small-SFX 生成。首次使用须先在模型供应流程确认 Stability AI 对应的 Community/Enterprise 身份、Stability 注册及 Gemma 条款，并通过真实 CUDA 质量门；模型未安装、许可回执过期或质量门未通过时，平台会保持禁用，不会联网临时下载或改用其他模型。

生成工作流为：根据句段起草 SoundPlan → 人工编辑英文 prompt 和语义锚点并批准 cue → 每个 cue 生成两个不可变候选 → A/B 试听后采用。只有采用的候选才进入正式素材库和 SFX/Ambience 时间线；未选候选保留到手工清理。生成任务在浏览器断开后仍会持久运行，GPU 忙时会明确提示，不会暗中排队。

采用后的片段以句段 start/end 加偏移作语义锚定。更换 Take、变速或对白交叉淡化后，Preview 与 Master 都按最新对白时间轴重算位置；文本变化会把 cue 标为 stale，Preview 仅警告，正式 Master/Release 会阻断到重新批准。Ambience 源素材按场景跨度循环，并使用交叉淡化避免硬接缝。

时间线片段可以设置位置、来源裁剪、循环、增益和淡入淡出。混音还可设置轨道总增益、对白交叉淡化和 BGM 自动闪避。

实用原则：

- 先保证对白清楚，再加音乐和音效；
- BGM 不要持续与人声争夺中频；
- SFX 应服务叙事，不要为了热闹频繁堆叠；
- 环境声宜稳定、低存在感，循环点不能明显；
- 自动闪避后仍要完整试听，避免音乐忽大忽小。

当前版本不生成 BGM，也不会自动挑选、静默生成或放置音效；所有生成候选都需要人工批准与采用。

## 10. Preview、质量检查与 Master

在“导出发布”中先点击“导出预览音频”。Preview 用于检查当前工程，不冻结 Take、编辑配方或声音设计。

完成全片试听后运行质量检查，优先处理阻断项：

- 缺失或未采用 Take；
- 分段未通过审听；
- 音频文件或哈希异常；
- 声音或素材授权记录缺失；
- 响度、真峰值或输出格式不符合要求。

当前混音默认目标为 -16 LUFS、-1.5 dBTP，正式 Master 输出为 48 kHz / 24-bit。这只是项目默认值，不替代目标发布平台的当期规范；发布前应按平台要求调整并复测。

质量检查通过后点击“生成正式 Master”。Master 会冻结当时使用的 Take、编辑配方、声音设计和文件校验值；后续修改工程不会改变旧 Master。

可以按用途保留多个 Master，例如“播客标准版”“故事纯人声版”“短视频节选版”。每次生成前都要确认当前声音设计和发布目标正确。

## 11. 字幕与 Release Package

字幕模型选择：

- `large-v3-turbo`：中英文默认推荐；
- `large-v3`：质量优先、速度更慢；
- `distil-large-v3`：只建议纯英文。

中文词级时间轴可使用项目内 WhisperX 中文对齐模型。自动字幕仍需人工校对人名、专有名词、数字、标点和断句。

为目标 Master 填写标题、简介、作者、系列、期号、版权声明和封面，再点击“生成发布包”。通用 ZIP 可包含：

- WAV 和 MP3；
- SRT 和 VTT；
- 章节信息；
- 封面和发布元数据；
- 声音、音乐和音效授权/署名清单；
- 文件校验和。

`credits_and_licenses.json` 会按设计保存生成音频的完整 provenance，包括英文
prompt、seed、生成时间和许可确认元数据。对外发布前应检查这些字段是否会透露
尚未公开的剧情或制作信息；这是为了可追溯性而进行的明确披露，不是匿名统计。

生成后解压 ZIP，逐项检查可播放性、字幕编码、封面、署名和校验和。本项目不会自动上传喜马拉雅、今日头条、番茄畅听或抖音；发布前应在各平台后台核对当期格式、响度、封面、AI 内容标识和授权要求。

## 12. 保存、关闭与备份

角色、分段、采用 Take、编辑配方、审听、声音设计和任务进度会随操作保存到项目数据目录。关闭平台前应先停止正在运行的批量任务和 TTS 工作进程，避免依赖强制结束进程。

重要节点建议创建冷备份：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup_project.ps1 -ValidateOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup_project.ps1
```

默认项目位于 `dubbing_projects/`。如果 `DUBBING_PROJECTS_ROOT` 指向仓库外数据盘，默认备份脚本不会自动包含该目录，必须单独备份。

默认备份不包含 API Key、普通模型权重或 Stable Audio 许可回执，但会包含作品文本、参考声音和授权素材，应加密保存且不要上传公共仓库。恢复后重新确认相同许可文本与同一 Community/Enterprise 层级时会生成新的回执 ID，这是正常现象；历史生成素材保留原 ID 作为审计记录，仍可继续使用。许可文本哈希或层级变化时，采用、Master 和 Release 仍会被阻断。

## 13. 建议的日常生产节奏

1. 整理原稿、章节和角色 Voice Bible；
2. 分段并校正文案；
3. 用 3～5 段锁定音色和参数；
4. 批量生成，其间不切换 TTS 后端；
5. 逐段 A/B、保存非破坏编辑并审听；
6. 连续听完整 Dialogue；
7. 加 BGM、Ambience 和 SFX；
8. 导出 Preview，在耳机和普通扬声器上复听；
9. 质检并生成 Master；
10. 校对字幕、补齐元数据和授权，生成发布包；
11. 完整复听并冷备份工程与发布包。

## 14. 不要这样做

- 不要同时运行两个平台实例写同一个项目目录；
- 不要把三个 uv 环境合并；
- 不要在模型运行时切换或删除模型目录；
- 不要直接结束批量合成进程，优先使用 UI 的停止与继续功能；
- 不要在已有正式 Take 的项目中无备份地重新自动分段或导入 JSON；
- 不要用“渲染为新 Take”替代正常的编辑配方保存；
- 不要在未完整试听时批量标记通过；
- 不要把 API Key、作品、声音、模型或输出强制加入 Git；
- 不要把无认证的 9000 端口暴露公网；
- 不要把技术可用误当作已经取得商业授权。
